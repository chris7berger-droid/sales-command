### High

- **B-archive-grant-anon** — **`archive` schema `GRANT ALL … TO anon` with ALTER DEFAULT PRIVILEGES** (NEW)
  - `sql/history_locker_phase1.sql:118-122`
  - Evidence: `GRANT ALL ON ALL TABLES IN SCHEMA archive TO anon, authenticated; GRANT ALL ON ALL SEQUENCES IN SCHEMA archive TO anon, authenticated; ALTER DEFAULT PRIVILEGES IN SCHEMA archive GRANT ALL ON TABLES TO anon, authenticated;`
  - Anon is granted full DML on `archive.import_batches` and `archive.legacy_records`, and `ALTER DEFAULT PRIVILEGES` auto-grants every future archive table to anon. Data protection today rests entirely on the RLS policies at :86-109 which use `archive.get_user_tenant_id()` returning NULL for anon → predicate NULL → rows denied. Two defense-in-depth failures: (a) the RLS policies do NOT specify `TO authenticated`, so they default to PUBLIC — one future policy with `USING (true)` inherits anon access; (b) the RLS policies cover only SELECT/INSERT/DELETE, no UPDATE — but the GRANT includes UPDATE, so any future permissive UPDATE policy opens a write path for anon. Legacy seed file; prod state may differ, but a fresh deploy from this seed re-establishes the grants.
  - Spec: `CLAUDE_RLS.md` (least privilege), OWASP-ASVS V8.1.5, OWASP A05.
  - Fix: `GRANT ... TO authenticated` only (drop anon); scope every RLS policy with `TO authenticated`; `ALTER DEFAULT PRIVILEGES ... TO authenticated` only.

- **B-PublicInvoicePage-wide-select** — **`PublicInvoicePage` leaks `proposal_wtc.*` (burden_rate, markup_pct, materials) to anon viewers**
  - `src/pages/PublicInvoicePage.jsx:51`
  - Evidence: `.from("invoice_lines").select("*, proposal_wtc(*, work_types(name))").eq("invoice_id", inv.id);`
  - Anon token-gated select on `invoice_lines` joins `proposal_wtc(*)` — the response ships `regular_hours, ot_hours, burden_rate, ot_burden_rate, markup_pct, materials (jsonb cost basis), travel, discount, sales_sow, field_sow, sub_areas` — internal cost + margin — to every invoice recipient's browser. The sibling `PublicSigningPage` was hardened against this in the H6/2026-05-02 cycle via a SECURITY DEFINER RPC; `PublicInvoicePage` was never migrated. Line 214 calls `calcWtcPrice(wtc, ...)` client-side, confirming these fields cross the wire. Anyone with a valid viewing token — or anyone the token leaks to (a forwarded email, an intermediate MTA log) — can read your labor rates and material cost basis. D2 carry-over, third audit cycle.
  - Spec: `CLAUDE.md`, `CLAUDE_RLS.md`, OWASP-ASVS V5.1.3, OWASP A01.
  - Fix: mirror the H6 pattern — add `get_public_invoice_view(p_token uuid)` SECURITY DEFINER RPC returning only invoice header + per-line `{wtc_name, wtc_index, line_amount, billing_pct, locked_line_total}`; delete the direct `invoice_lines` select and the client-side `calcWtcPrice` call.

- **B11 (legacy-seed)** — **`sql/rls_identity_tables.sql:64` still ships the pre-lockdown `team_members_update` policy**

- **A4** — **`invite-user` logs full magic-link `action_link` via the `linkData` object**

  - Spec: OWASP-ASVS V7.1.1, OWASP A09.
