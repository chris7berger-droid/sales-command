### High

- **A4** — **`invite-user` logs full magic-link `action_link` via the `linkData` object**
  - `supabase/functions/invite-user/index.ts:128`
  - Evidence: `console.log("generateLink result:", { linkData, linkErr: linkErr?.message });`
  - `linkData.properties.action_link` is a single-use magic-link URL that authenticates the invitee (redirectTo=`https://salescommand.app`). Written to Supabase function logs on every invite; anyone with log-read access can claim the account before the legitimate invitee. Carry-over from 2026-06-01/2026-06-28 A4 — still at the same line, third audit cycle in a row.
  - Spec: OWASP-ASVS V7.1.1, OWASP A09.
  - Fix: `console.log("generateLink result:", { hasLink: !!linkData?.properties?.action_link, linkErr: linkErr?.message });`

### Medium

- **A1** — **Hardcoded Supabase project URL fallback in `supabasePublic.js`**
  - `src/lib/supabasePublic.js:16`
  - Evidence: `const SUPABASE_URL = import.meta.env.VITE_SUPABASE_URL || "https://pbgvgjjuhnpsumnowuym.supabase.co";`
  - A misbuilt non-prod deploy silently routes to prod; project ref baked into every browser bundle. Carry-over from prior audits.
  - Spec: OWASP-ASVS V14.3.2, 12-factor III.
  - Fix: drop the `||` fallback and throw at module load like `src/lib/supabase.js:8` already does.

- **A2** — **Hardcoded Supabase publishable-key fallback in `supabasePublic.js`**
  - `src/lib/supabasePublic.js:20`
  - Evidence: `const SUPABASE_KEY = import.meta.env.VITE_SUPABASE_ANON_KEY || "sb_publishable_LL6wYC7kJDPQfGYeKAaLaWKoK";`
  - After anon-key rotation, stale bundles keep authenticating with the OLD key. Not a bearer secret, but defeats the whole point of env-var rotation. Carry-over.
  - Spec: OWASP-ASVS V14.3.2, OWASP A05.
  - Fix: remove the literal; require the env var (throw on missing).

- **A1b** — **Hardcoded URL fallback on Login forgot-password path**
  - `src/pages/Login.jsx:59`
  - Evidence: `` `${import.meta.env.VITE_SUPABASE_URL || "https://pbgvgjjuhnpsumnowuym.supabase.co"}/functions/v1/reset-password` ``
  - Same rotation hazard as A1. Carry-over (line moved 58→59).
  - Spec: OWASP-ASVS V14.3.2.
  - Fix: import from `src/lib/supabase.js`.

- **A2b** — **Hardcoded publishable-key fallback on Login (DIFFERENT literal than A2 — key drift)**
  - `src/pages/Login.jsx:62`
  - Evidence: `apikey: import.meta.env.VITE_SUPABASE_ANON_KEY || "sb_publishable_v7XktVvkAlX7y5f6xoFjng_AaLaWKoK"`
  - The literal here (`v7XktVvkAlX7y5f6xoFjng_…`) still differs from the literal in `supabasePublic.js:20` (`LL6wYC7kJDPQfGYeKAaLaWKoK`). Exactly the rotation-drift the audit has been calling out for months. Carry-over (line moved 61→62).
  - Spec: OWASP-ASVS V14.3.2, OWASP A05.
  - Fix: remove both literals; require the env var everywhere.

### Low

- **A5** — **`stripe-webhook` logs full recipient email for every outbound receipt**
  - `supabase/functions/stripe-webhook/index.ts:49`
  - Evidence: `console.log("Email to", to, ":", res.status);`
  - Customer email address written to function logs on every payment-receipt send. PII in logs; searchable index of who's getting paid emails. Carry-over.
  - Spec: OWASP-ASVS V7.1.1, OWASP A09, GDPR Art. 5(1)(c).
  - Fix: `console.log("Email send status:", res.status);` — drop `to`.

- **A6** — **`invite-user` logs invitee + sender emails and names on every call** (NEW)
  - `supabase/functions/invite-user/index.ts:88`
  - Evidence: `console.log("invite-user invoked", { email, name, teamMemberId, senderEmail, senderName });`
  - Every invite writes invitee email + name + inviter email + name to function logs. Same PII-in-logs class as A5; enumerable by anyone with Supabase log access.
  - Spec: OWASP-ASVS V7.1.1, OWASP A09, GDPR Art. 5(1)(c).
  - Fix: log only `{ hasEmail: !!email, teamMemberId }`.

- **A7** — **`send-proposal` logs recipient + rep emails on every send** (NEW)
  - `supabase/functions/send-proposal/index.ts:139`
  - Evidence: `console.log("send-proposal invoked", { proposalId, recipientEmail, repEmail, proposalNumber });`
  - Same PII-in-logs pattern. Every proposal-send writes customer + rep emails.
  - Spec: OWASP-ASVS V7.1.1, OWASP A09.
  - Fix: log only `{ proposalId, proposalNumber, hasRecipient: !!recipientEmail }`.
