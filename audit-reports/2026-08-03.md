- **B-archive-grant-anon** — **`archive` schema `GRANT ALL … TO anon` with ALTER DEFAULT PRIVILEGES** (NEW)
  - `sql/history_locker_phase1.sql:118-122`
  - Evidence: `GRANT ALL ON ALL TABLES IN SCHEMA archive TO anon, authenticated; GRANT ALL ON ALL SEQUENCES IN SCHEMA archive TO anon, authenticated; ALTER DEFAULT PRIVILEGES IN SCHEMA archive GRANT ALL ON TABLES TO anon, authenticated;`
  - Anon is granted full DML on `archive.import_batches` and `archive.legacy_records`, and `ALTER DEFAULT PRIVILEGES` auto-grants every future archive table to anon. Data protection today rests entirely on the RLS policies at :86-109 which use `archive.get_user_tenant_id()` returning NULL for anon → predicate NULL → rows denied. Two defense-in-depth failures: (a) the RLS policies do NOT specify `TO authenticated`, so they default to PUBLIC — one future policy with `USING (true)` inherits anon access; (b) the RLS policies cover only SELECT/INSERT/DELETE, no UPDATE — but the GRANT includes UPDATE, so any future permissive UPDATE policy opens a write path for anon. Legacy seed file; prod state may differ, but a fresh deploy from this seed re-establishes the grants.
  - Spec: `CLAUDE_RLS.md` (least privilege), OWASP-ASVS V8.1.5, OWASP A05.
  - Fix: `GRANT ... TO authenticated` only (drop anon); scope every RLS policy with `TO authenticated`; `ALTER DEFAULT PRIVILEGES ... TO authenticated` only.
