- **A4** — **`invite-user` logs full magic-link `action_link` via `linkData`**
  - `supabase/functions/invite-user/index.ts:128`
  - Evidence: `console.log("generateLink result:", { linkData, linkErr: linkErr?.message });`
  - `linkData.properties.action_link` is a single-use magic-link that signs the invitee in and lets them set a password. Written to Supabase edge-function logs on every invite — anyone with log-read access (or a future log breach / third-party sink) can hijack the newly-invited account before the legitimate invitee redeems it. Fourth audit cycle in a row.
  - Spec: OWASP-ASVS V7.1.1, OWASP A09.
  - Fix: `console.log("generateLink result:", { hasLink: !!linkData?.properties?.action_link, linkErr: linkErr?.message });` — never log linkData.

- Bumped to **HIGH** for the log-secret class per severity rubric (single-use auth link in logs = exploitable by any actor with log access).

- **A8** — **`send-proposal` logs full Resend response body (echoes recipient on error)** (NEW)
  - `supabase/functions/send-proposal/index.ts:184`
  - Evidence: `console.log("Recipient email response:", customerRes.status, customerResBody);`
  - `customerResBody` is Resend's raw JSON — on validation-failure paths Resend echoes the offending `to` address plus internal error text. Second PII surface beyond line 139, and the raw body is later interpolated into the client error response at :187 (`\`Failed to send email: ${customerResBody}\``) so a diagnostics message from Resend surfaces to the browser too.
  - Spec: OWASP-ASVS V7.1.1, OWASP A09.
  - Fix: log status only; parse and log only `{ id }` on success; return a generic 500 to the client and keep the body server-side.

- **A10** — **`_shared/repNotify.sendEmail` logs recipient email + Resend response body on success** (NEW)
  - `supabase/functions/_shared/repNotify.ts:118`
  - Evidence: `console.log(\`${tag}: emailed ${to} — ${body}\`);`
  - Shared helper logs the rep's email address on every proposal-approved / follow-up-reminders send AND dumps Resend's full response body. Multiplies the PII log surface across the two new callers (proposal-approved, follow-up-reminders). The intent (:113 comment) is loud-on-failure to avoid silent send drops — the success path doesn't need `to` in the log line.
  - Spec: OWASP-ASVS V7.1.1, OWASP A09.
  - Fix: log a Resend id only on success (parse `body` for `id`), drop `to`; keep the error-path detail as-is if the failure-visibility goal requires it.

  - New nightly cron dumps job numbers paired with rep names on every run when any rep is inactive/missing. Internal-only PII, but noisier per-run than the per-invocation logs.
  - Spec: OWASP-ASVS V7.1.1.
  - Fix: log a count only; persist detail to a `follow_up_reminder_failures` table if the operator needs it.

- **A12** — **`reset-password` logs full Resend response body** (NEW)

  - Spec: OWASP-ASVS V7.1.1, OWASP A09.
