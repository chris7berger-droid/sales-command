## Top 3 Urgent

1. **`D-QBCallbackPage-state` (HIGH — NEW) — QuickBooks OAuth callback does not verify the `state` parameter, and the auth-URL builder ships a hardcoded `state=salescommand`.** `src/pages/QBCallbackPage.jsx:8-9` reads only `code` and `realmId`; `state` is never read or compared. `src/pages/Settings.jsx:417` bakes `state=salescommand` into `QB_AUTH_URL`. An attacker who initiates their own QB OAuth flow, obtains their own `code` + `realmId`, and lures a signed-in admin to `/qb/callback?code=X&realmId=Y` will cause the victim tenant's `qb_connection` to be overwritten with attacker-controlled tokens — redirecting invoice sync into the attacker's QuickBooks. Classic RFC 6749 §10.12 CSRF. Fix: generate `crypto.randomUUID()` state before redirect, store in `sessionStorage`, reject callback if `params.get("state")` doesn't match — and bind + verify server-side in `qb-auth`.

2. **`C-extract-sov-ssrf` (HIGH — sharper framing of prior C-extract-sov rate-limit) — `extract-sov` fetches an arbitrary user-controlled URL and forwards its bytes to Anthropic.** `supabase/functions/extract-sov/index.ts:141` calls `fetch(pdf_url)` with only an RLS-visible ownership check on `billing_schedule.contract_pdf_url` — the URL's host is never restricted to Supabase storage. Any user with a JWT and INSERT rights on their tenant's `billing_schedule` can seed a row with a link-local metadata endpoint, an internal Supabase host, or an attacker-controlled site and cause the Edge Function to fetch it. No `Content-Length` cap, no timeout, no MIME check — same request also drains Anthropic budget on arbitrary-size PDFs. Contrast with `send-invoice`/`send-pay-app` which validate via `isAllowedStorageUrl()`. Fix: validate `pdf_url` against `isAllowedStorageUrl()`, reject non-PDF Content-Type, cap Content-Length (~25 MB), wrap fetch in `AbortSignal.timeout(20000)`.

3. **`B-proposal_wtc-anon-grant` (HIGH — third audit cycle unfixed) — `proposal_wtc` cost basis and margin still reachable via direct PostgREST by any public-link holder.** The in-code comment at `src/pages/PublicInvoicePage.jsx:60-67` documents the residual vector: the 2026-08-10 DOM allow-list narrowed what THIS page selects, but the table-level anon SELECT grant remains — a holder of a valid `viewing_token` or `signing_token` can call PostgREST directly with the token header and read `burden_rate`, `ot_burden_rate`, `markup_pct`, `pw_rate`, `materials` (jsonb), and `discount` on every WTC in scope. Backlog S13. Fix: mirror the invoices column-grant pattern in `command-suite-db` — `REVOKE SELECT ON public.proposal_wtc FROM anon`, then `GRANT SELECT` only on non-cost columns (`id, proposal_id, work_type_id, is_rate_card, rate_class, rate_amount, locked_line_total, sales_sow`).
