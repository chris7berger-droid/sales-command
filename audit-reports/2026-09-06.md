### High

- **A4 (Pass A)** — **`invite-user` logs full magic-link `action_link` on every invocation** (carry-over, 4th cycle)
  - `supabase/functions/invite-user/index.ts:128`
  - Evidence: `console.log("generateLink result:", { linkData, linkErr: linkErr?.message });`
  - `linkData.properties.action_link` is a single-use magic link that authenticates the invitee (redirectTo `https://www.scmybiz.com`). Written to Supabase function logs on every invite; anyone with log-read access can claim the account before the legitimate invitee. Carry-over from 2026-06-01, 2026-06-28, 2026-08-03 — still at the same line, fourth audit cycle in a row.
  - Spec: OWASP-ASVS V7.1.1, OWASP A09.
  - Fix: `console.log("generateLink result:", { hasLink: !!linkData?.properties?.action_link, linkErr: linkErr?.message });`

### Medium

- **A1 / A1b (Pass A)** — **Hardcoded Supabase URL + publishable-key fallbacks defeat env-var rotation** (carry-over)
  - `src/lib/supabasePublic.js:14-20` and `src/pages/Login.jsx:73` (URL), `:76` (apikey)
  - Evidence (supabasePublic.js:14-20): `const SUPABASE_URL = import.meta.env.VITE_SUPABASE_URL || "https://pbgvgjjuhnpsumnowuym.supabase.co"; const SUPABASE_KEY = import.meta.env.VITE_SUPABASE_ANON_KEY || "sb_publishable_LL6wYC7kJDPQfGYeKAaLaWKoK";`
  - Evidence (Login.jsx:73,76): `${import.meta.env.VITE_SUPABASE_URL || "https://pbgvgjjuhnpsumnowuym.supabase.co"}/functions/v1/reset-password` … `apikey: import.meta.env.VITE_SUPABASE_ANON_KEY || "sb_publishable_v7XktVvkAlX7y5f6xoFjng_AaLaWKoK"`
  - Two failure modes: (1) a misbuilt non-prod deploy with a missing env var silently routes to prod; (2) after any anon-key rotation, stale bundles keep authenticating with the OLD key. The Login.jsx literal (`v7Xkt…`) still DIFFERS from the supabasePublic.js literal (`LL6wYC7…`) — a key-drift the audit has been calling out for months. `src/lib/supabase.js:7` already does it correctly (throws on missing env var).
  - Spec: OWASP-ASVS V14.3.2, OWASP A05, 12-factor III.
  - Fix: drop both `||` fallbacks; throw at module load like `src/lib/supabase.js:7` does.

### Low

- **A6 (Pass A)** — **`invite-user` logs invitee + inviter emails on every call** (carry-over)
  - `supabase/functions/invite-user/index.ts:88`
  - Evidence: `console.log("invite-user invoked", { email, name, teamMemberId, senderEmail, senderName });`
  - Every invite writes invitee email + name + inviter email + name to function logs. PII in logs; searchable index of onboarding activity across the tenant.
  - Spec: OWASP-ASVS V7.1.1, OWASP A09, GDPR Art. 5(1)(c).
  - Fix: `console.log("invite-user invoked", { hasEmail: !!email, teamMemberId });`

- **A5 (Pass A)** — **`stripe-webhook` logs full recipient email for every outbound receipt** (carry-over)
  - `supabase/functions/stripe-webhook/index.ts:49`
  - Evidence: `console.log("Email to", to, ":", res.status);`
  - Customer email address written to function logs on every payment-receipt send. Searchable index of who paid what and when.
  - Spec: OWASP-ASVS V7.1.1, OWASP A09, GDPR Art. 5(1)(c).
  - Fix: `console.log("Email send status:", res.status);` — drop `to`.

- **A7 (Pass A)** — **`send-proposal` logs recipient + rep emails on every send** (carry-over)
  - `supabase/functions/send-proposal/index.ts:139`
  - Evidence: `console.log("send-proposal invoked", { proposalId, recipientEmail, repEmail, proposalNumber });`
  - Same PII-in-logs pattern as A5/A6. Every proposal-send writes customer + rep emails to function logs.
  - Spec: OWASP-ASVS V7.1.1, OWASP A09.
  - Fix: `console.log("send-proposal invoked", { proposalId, proposalNumber, hasRecipient: !!recipientEmail });`

- **A8 (Pass A, NEW)** — **`_shared/repNotify.sendEmail` logs rep email + full Resend body on every success** (NEW; called from every proposal-approved/proposal-signed notification path)
  - `supabase/functions/_shared/repNotify.ts:118` (success path); also `:99`, `:115`, `:121`, `:141` (failure paths log `to` too)
  - Evidence: `console.log(\`${tag}: emailed ${to} — ${body}\`);`
  - New shared helper added since 2026-08-03. Both invitee's email address AND full Resend response body (message id, delivery echo) written to logs on every rep notification. Any Sales rep decision surfaces the rep's email in a searchable log index.
  - Spec: OWASP-ASVS V7.1.1, OWASP A09.
  - Fix: success path — `console.log(\`${tag}: sent\`);`. Keep loud failure logging but obfuscate email (`to.replace(/(.).*(@)/, '$1***$2')`).

- **A9 (Pass A, NEW)** — **`send-invoice` logs first 200 chars of main-recipient Resend response body** (NEW/touched Sep 7)

  - Spec: OWASP-ASVS V7.1.1, OWASP A09.

  - Fix: log status only on success; keep body only on `!customerRes.ok` as `console.error`.
