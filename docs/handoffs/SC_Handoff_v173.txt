SESSION SUMMARY
---------------
Chris opened /calllog/3653 and asked how to add an attachment. The capability already existed and
worked — "+ Upload Files" has been on Job Detail since 2026-03-20 (c84d801), and prod storage policies
were verified allowing public INSERT/SELECT on the `job-attachments` bucket. The real problem was
visual: the upload control and the attached-file chips wore the SAME treatment (C.dark background,
C.teal text, borderRadius 6, same font and size, same row region), so when moving fast the button read
as a fourth attached file. Chris: "when moving fast, the button looks exactly like an attachment."

So this was an affordance fix, not a missing feature. Two options were put to Chris:
  A. Solid teal fill + black text — matches "+ NEW PROPOSAL", the app's existing action language.
  B. Dashed-outline drop zone with drag-and-drop — obviously not a file, and faster than the picker.
Chris ratified B. Two iterations followed from his eyeball on the preview: the first pass was a
full-bleed card ("not as far as I know... don't go full bleed on the upload bubble, it's too much"),
so it was shrunk to an inline-block sized to its own text; then "make it twice as tall" for a bigger
drag target. Shipped at that shape.

mid-upload, with the click and drop paths both disabled.


DECISIONS
---------
1. The chips stay as-is (C.dark + C.teal). The distinction being drawn is FILES = dark chips,
   ACTIONS = dashed outline. Don't "fix" the chips to match the button later — that would collapse
   the very distinction this change created.
2. Drag-and-drop was chosen over the cheaper teal-fill button because it also improves the actual
   ergonomics, not just the legibility. It cost ~30 min more.
3. No backlog row was opened or closed — this never had one. Logged in the Completed Log with ID "—".
4. Deliberately NOT run: /auditcriteria, /runaudit, /buildvsplan, /code-review. UI-only, single file,
   no money path, no data path, no auth path. `vite build` green was the gate.
