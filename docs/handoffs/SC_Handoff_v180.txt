had no home and got attributed to the "Specialty" work type. Chris wanted a proper
"T&M Material" cost code. That surfaced two code bugs along the way.

  1. eaec04d — Settings → Work Types "Add/Edit" fail-silent fix
     WorkTypesSection.save() (src/pages/Settings.jsx) swallowed every insert/update
     error — a blocked add closed the form and showed nothing, reading as "I can't
     add a work type." Now .select()s the write (like remove() already did), guards
     a null tenant_id, and renders any error in the EditRow. CLAUDE.md rule #6.

  2. b07ed83 — "T&M Material" no longer trips the rate-card panel
     WTCCalculator.jsx handleWorkTypeChange decided the hourly rate-card panel with
     /t\s*&\s*m/i.test(name) — i.e. any name CONTAINING "T&M". "T&M Material" matched,
     so it demanded a rate class / rate-per-hour. Anchored to /^\s*t\s*&\s*m\s*$/i —
     only a name that IS "T&M" (the labor rate card) triggers it. Every downstream
     surface already keys off the stored is_rate_card flag, so this was the only site.
