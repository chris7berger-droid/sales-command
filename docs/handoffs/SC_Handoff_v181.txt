1. F44 — Rate cards no longer count as contract dollars   [merge dc4f0a3, live]
   A T&M rate card is an hourly rate sheet, not committed work, so it must carry
   $0 of fixed contract value. It was flowing through the same fixed-total sums as
   real work types and inflating every "contract value" figure — surfacing as a
   phantom "Remaining on contract" the Job Totals ledger invited someone to bill.
   - calcProposalTotal (calc.js) now EXCLUDES is_rate_card and is the single
     contract-value primitive; all six fixed-total sum-sites route through it
     (ProposalDetail total writer, WTCCalculator x2, ProposalPDFModal signed
     price, MultiGCWizard x2, SOV seeding).
   - The per-line BILLING primitive calcWtcPrice was DELIBERATELY NOT touched —
     zeroing it is the archive/pay-app invoice-zeroing trap (CLAUDE.md Data #6).
     Safe because T&M bills via day-rows, and the billing sites already branch
     is_rate_card away from calcWtcPrice.
   - Rate cards RENDER as an hourly rate ("$105/hr · Regular") — not a fixed line
     price — on proposal detail, the proposal PDF, and the public signing page.
     New pure helper rateCardLabel() in utils.js. Per Chris: no "(1.5x)"
     multiplier and no "billed as incurred" suffix on the customer surfaces.
   - Migration 20260810170000 (command-suite-db 87f9dda): get_public_proposal_view
     carries is_rate_card / rate_amount / rate_class so the signing page can render
     the rate. CREATE OR REPLACE restated SECURITY DEFINER + search_path + anon
     grant. `total` stays p.total (auto-corrects via the writers). Rehearsed
     --against-prod green, no new anon exposure, pushed live + verified.

2. T&M void/reissue — reworked to VOID + DELETE + REBUILD   [merge a2707d4, live]
   Started as a verification of the shipped void/reissue path; became a design fix.
   - On a T&M invoice, "Pull Back" now VOIDS (in QuickBooks if synced) + DELETES
     the invoice, with a modal note telling the user to RECREATE FROM SCRATCH.
     No auto-reissue. Detection: isTMInvoice = invoice has is_rate_card day-row
     lines (Invoices.jsx). QB void still runs with the required reason for audit;
     test-named invoices bypass the real QB call.
   - REGULAR invoices keep the existing carry-forward reissue UNCHANGED. The
     divergence is intentional and T&M-only.
   - WHY: a T&M day-row's HOURS can't be edited once billed (preserve-only, Data
     #6), and there is no day-row editor on the existing-invoice screen — only on
     the create screen. So carrying day-rows into a reissue leaves frozen rows.
     Voiding + rebuilding routes the user back to the create flow, the only place
     day-rows are editable. Chris weighed and chose this over building in-place
     T&M editing (much bigger for little gain).

3. Delete clears the invoice-number search   [in a2707d4, live]
   Deleting the invoice you searched for left its number in the FilterBar, so the
   list came back filtered-to-nothing (blank). onDeleted now clears
   filters.invoiceNumber. Applies to every delete path.
