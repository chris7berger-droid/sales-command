First task of the new Schedule polish/fixes stream (opened by v208). Fixed the

THE BUG (what the user saw)
------------------------------------------------------------
Crew Schedule showed crews marked "double-booked" for days where they were only
on one visible job — the phantom second job wasn't on the board that week.


ROOT CAUSE (traced, not guessed)
------------------------------------------------------------
- Double-book detection (`crewDayJobs`, src/schedule/views/Schedule.jsx) counted
  EVERY assignment row dated in the viewed week (fetchWeekData pulls all rows
  gte/lte the week's Mon–Sat), grouping crew -> date -> jobIds; >1 job on a day
  = double-booked.
- But the board only renders `weekJobs` (active jobs overlapping the week). Stray
  assignments for OFF-board jobs — e.g. an old HDSP-imported crew-day dated
  outside that job's own schedule range (job 10053 runs Aug 24–Sep 4 yet has a
  Jul 27 crew row) — were still counted, flagging a double-book against a job
  the user can't even see.
- Confirmed the current app CANNOT create such rows: the assign modal
  (Schedule.jsx ~L1134) greys out and disables any day outside a job's range, so
  out-of-range crew-days only enter via IMPORT, not normal use. That's why the
  display-layer fix is the correct, permanent fix for the symptom.


FIX SHIPPED (commit ed7a676, pushed to main)
------------------------------------------------------------
- src/schedule/views/Schedule.jsx:
  * New `weekJobIds` memo = Set of String(job_id) for the jobs on the board this
    week (derived from `weekJobs`).
  * `crewDayJobs` now skips any assignment whose job_id isn't in `weekJobIds`
    (`if (!weekJobIds.has(String(a.job_id))) continue`).
  * Moved `crewDayJobs` (and added `weekJobIds`) to just AFTER `weekJobs` is
    declared, so it can reference it without a use-before-declare (TDZ) error.
    `getDoubleBookedDays`/`isDoubleBooked` stay above as function declarations —
    they only read `crewDayJobs` at call time (render), so ordering is safe.
- Real double-books (two ON-board jobs, same crew, same day) still flag —
  detection is scoped, not disabled.
- Build: `npm run build` green.
