DECISIONS
---------
- Deliberate divergence from the plan's UI mockup: the mobilization panel does
  NOT collect crew#/lead/prevailing-wage inputs. addJobMobilization only persists
  seq/label/dates/is_go_back — those inputs have no write target, and adding
  jobs-row writes to capture them would reintroduce the exact mutation the
  guardrail removes. The picked job already carries its own crew/PW; crew is
  assigned on the grid. buildvsplan + code-review both confirmed this is correct
  (mechanism over mockup; no required function lost).
- "Unallocated view" in workstream A = the queries.js data helper
  (loadUnallocatedJobs) only. The actual screen is workstream B — a new view file
  would exceed the plan's 3-file scope.
- attachDepositState left unchanged: already null-safe on orphan rows
  (.filter(Boolean) on call_log_id; depositState returns null for a null key).
