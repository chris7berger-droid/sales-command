DECISIONS / CHOICES MADE
------------------------
- Stop-and-merge-guardrail (B over "finish everything first"): once the allocation
  half revealed it needs a migration + multi-view rework + hit a DB-baseline
  blocker, Chris chose to merge the safe, gated guardrail now and do the allocation
  work in a fresh terminal. Guardrail has no DB dependency, so the merge is clean.
- Allocations carry their OWN details (crew size, lead, vehicle, equipment, power,
  scope) — a return trip runs different crew/scope than the first run, so it can't
  inherit them. Prevailing wage is the exception: it's set when the job is sold, so
  every allocation inherits the job's PW (not per-trip). This is why B86's "+ Job"
  panel shows only date + go-back for now — those fields had nowhere to save until
  the B87 migration adds the columns.
- Park the pending migration OUTSIDE supabase/migrations/: `supabase db push` sweeps
  that folder, so leaving an uncommitted migration there risked it riding along on
  the other terminal's (schedule-import) push. Moved to docs/pending-migrations/*.pending.
- buildvsplan T2-1 fix: paginated searchExistingJobs via loadAllRows — an unpaginated
  id-DESC fetch would silently drop the OLDEST jobs past 1000 rows and wrongly block
  a trip on an old job. T2-2 was a plan-doc reason correction (StatsBar), no code.
