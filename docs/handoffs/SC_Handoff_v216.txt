DECISIONS / CHOICES MADE
------------------------
- Scoped-verify replaces open-ended smoke (Chris, ratified this session; saved as
  a memory). Open smoke on complex features caused scope-bleed: Chris finds
  unrelated breakage, folds it into the fix, we churn. New protocol: Claude holds
  verification (data/logic, or driving the app), or hands a 3-line click/expect
  with a hard "anything else = ADJACENT, don't touch" rule. All B87/B88 verification
  this session was done this way, no previews.
- Built B87 in this (warm) terminal instead of a fresh one — the load-bearing
  discipline is that the GATES run cold, not that the build is pristine; and this
  terminal already held live DB context B87 needed. Gates were still run cold.
- B88 #5 is Admin-only, NOT Admin+Manager. The other money tables use
  is_admin_or_manager(); the billing worklist is deliberately tighter to match
  Billing.jsx canEdit === 'Admin' and Chris's literal ask. Added a new is_admin()
  helper mirroring the canonical one.
- migration_backup drop: the /resume note called it a push blocker. It wasn't — it
  only matters when re-baselining. Dropped it anyway (verified 131/140 rows orphaned,
  9 were test-job audit rows) so a future `db dump` stays clean.
- B91 part-1 (suite-wide anon DML revoke) DEFERRED ON PURPOSE. Zero real exposure
  today (RLS blocks anon everywhere; no anon page reads these tables). "Suite-wide
  revoke" is a per-table audit with real risk of breaking public pages (invoices/
  proposals — same class as the stripe_checkout_url leak). Not a reactive knockout.
