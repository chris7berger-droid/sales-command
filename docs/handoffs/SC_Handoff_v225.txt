CHANGES SHIPPED (PREVIEW ONLY)
----------------------------
- StageJobCard replaces the History tab with TripsPanel. Reads live trip rows
  directly and paginates all assignments for that job when the panel opens.
- Upcoming (ascending), Current dates, Past dates (descending), Dates to set.
  These are date categories, not claims about started/completed work.
- Each saved UUID appears once, even without crew. Explicit assignment links win
  over overlapping spans. Unlinked rows join a trip only if exactly one saved
  range contains their date. Ambiguous, out-of-range, or missing-link crew rows
  remain visible as separate Crew records, with the pre-existing gap >6 days
  fallback. No persisted links, dates, assignments, or trip identities rewritten.
- Expanded details label inherited job values, show each person's crew dates,
  and open Crew Schedule on that trip's start date. Unlinked crew records cannot
  be edited as if they were an explicit trip.
- Existing MobsModal now accepts initialEditId and edits crew need/lead, vehicle,
  equipment, power, scope text, and note as well as dates/label. Crew roster is
  Scheduling crew (name is its primary key; no id column), with archived-current
  lead preserved and loading/error/retry. Only changed operational fields are
  patched. Sequence, UUID, go-back type, and assignments are preserved.
- Update query now checks job_id as well as UUID, so a trip moved to another job
  after opening the editor cannot be edited under the stale parent.
- Editor date/range and crew-count validation; load errors visible. Original
  Planning editor still supports add/go-back/edit/delete; deletion logic unchanged.
- Jobs listens for trip updates alongside existing job/crew/material refreshes;
  explicit Refresh trips also available. No reliance on Realtime for correctness.
