CHANGES / DECISIONS
------------------
- Crew Schedule renders its own capacity header using the board's actual week,
  jobs, trips, assignments and crew-status data. Other routes keep their header.
- Prev/Next/This Week control both dates and daily figures; week deep links
  initialize both. Both dates have a 1.1-second teal feedback animation after
  navigation, none on initial render or unchanged This Week; reduced motion
  disables animation. Today's marker only appears on the actual date.
- Starting/Ending count planned trip endpoints within the Mon-Sat window,
  including return trips and parent-only job dates. Identical saved/parent spans
  are listed once. Assignment-derived history never invents a planned endpoint.
- Counts cover the same active jobs as the board. Count each Sales job once
  (call_log_id); unlinked jobs remain separate by job_id. A job can qualify for
  more than one bubble, with all matching trips retained in its clicked list.
- Needing Crew counts jobs with a known daily shortfall, using staffingForDay
  and distinct assigned names per job/date. Explicit zero needs nobody; blank
  inherits. Missing requirements / overlapping trips appear separately under
  Crew Needs to Check, never implied fully staffed or counted as known shortage.
- Summary dialogs show job and trip names, full trip spans for starts/ends, and
  dates plus assigned/needed/shortfall for shortages. Daily header click lists
  remain available and use the same selected week.
- Week loading hides old figures and board rows until that week's data arrives;
  failed jobs/trips/week loads show Retry. Stale week responses cannot replace
  the selected week. Trip loader has an opt-in throwOnError for this caller;
  all other callers retain existing behavior.
- Week navigation requires saving/cancelling an open trip draft first. Saves
  refresh the shared header inputs alongside the board.
