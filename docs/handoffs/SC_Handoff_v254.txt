GOVERNING LOGIC — IMPORTANT FOR FUTURE WORK
Source records remain assignments (crew_name, date, job_id, mobilization_id), with
jobs and job_mobilizations providing their identity and planned dates. Schedule
owns these via PostgREST. This change is a shared READ model, not a new writer.

1. crewWeekRows in lib/crewScheduleRows.js builds the selected week's rows ONCE
   in Schedule.jsx. It uses the existing buildJobTrips attribution: explicit trip
   UUID wins; NULL links can match exactly one date span at read time; ambiguous
   days become a separate legacy row. This fallback does NOT persist a trip link.
2. Planned active rows appear when dates overlap the week. A saved assignment
   keeps its row visible even if job dates/status would otherwise hide it.
   Assignments with unavailable job references become read-only issue rows.
   They remain booked, never silently freed. No guessed reassignment.
3. Board renders these rows. Sidebar crewCardRows projects the SAME rows for each
   person. The same row keys drive double-booking; colors come from the same row
   model. Multiple trips on one job can be separate sidebar entries, with trip
   information in their title. Crew availability still considers saved allocations.
4. CrewWeekCapacity receives the exact boardRows. crewWeekCapacity computes daily
   capacity from them, counting DISTINCT active roster people, not assignment
   records. Sick/off status keeps prior precedence: out of the available
   denominator. A double-booked person counts once in the percentage, with all
   their allocations listed together in day detail. Archived roster excluded.
5. crewWeekSummary receives those same rows for starting/ending/needing badges.
   It deduplicates by Sales call_log_id, checks trip-level planned dates/needs,
   and does not invent starts/requirements for unresolved legacy allocation rows.
6. Do NOT restore a separate job-date filter for sidebar/header or hide orphaned
   allocations to make counts look clean. Fix the allocation or surface the issue.
   The black header is not allowed to compute a contradictory booking model.
